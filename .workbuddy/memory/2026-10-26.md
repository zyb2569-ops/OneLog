# 2026-10-26

## PersonalWms 需求访谈（grill-me）完成，架构已锁定

**项目定位**：单人自用的个人物资管理系统 = 物资域（日用消耗品/衣物/食物）+ 日志域（饮食/运动/穿搭）+ 统计层 + 训练域 AI 分析。

**关键技术决策（已与用户逐条确认）**
- 平台：**仅 Android APK**（Capacitor 包壳），不做浏览器版、不做小程序
- 数据：**100% 本地**，无服务端、无云同步（用户最初想用自建 PostgreSQL 同步，后推翻）。原定的 HTTPS/域名/公网 IP/同步冲突方案全部作废
- 本地存储：IndexedDB + Dexie（浏览器与 WebView 行为一致、无原生依赖）
- 后端：无。若将来要同步，服务端只做"薄同步 + 备份"（厚客户端 + 薄同步的分层仍成立）
- AI：DeepSeek，OpenAI 兼容协议 + 可配 baseURL（便于换通义/智谱/Ollama），Key 存 Android Keystore
- AI 用途限定：**训练域**（训练计划生成 → 直接落为模板；单次训练后分析），手动点按钮触发。饮食域不用 AI
- UI：浅色卡片式

**数据建模决策**
- 统一基表 `items` + 域扩展表（consumables / garments / foods），`stock_logs` 三类共用
- 库存**只存流水不存当前值**，当前量 = 期初 + Σdelta（为了算消耗速率与预计用完日）
- 消耗品：计量型（ml/g）+ 计数型（件）混合，每件可选
- 食物库存**与饮食记录联动自动扣减**，混合策略：直接扣 / 按配方扣 / 外食不扣（每行独立选择）；库存不足允许为负并标红，绝不拒绝写入
- 训练模型：`训练 → 组块(block，可含 1~3 个动作，支持超级组) → 组(set) → 动作`。v1 每块默认单动作，结构预留
- 训练录入：**全部按组录**（重量×次数×组数），不做按动作类型切换
- 感受记录：每组可选 RPE 6-10 + 训练后标签（力竭/泵感/关节不适/睡眠不足）+ 一句话备注
- 组间歇：该组最后动作完成后自动进入倒计时，时长可配（本次训练级 / 全局级两层），原生本地通知（Capacitor LocalNotifications，非 JS setTimeout），结束播放音频 + 震动
- 统计口径：**摄入与运动分开，不做加减**（避开运动消耗 20-30% 估算误差）；身体指标记体重 + 围度 + 体脂，BMR 用 Mifflin-St Jeor 自动算可手填覆盖
- 饮食记录：**流水式不分餐次**，但按时间戳自动落到 早/午/晚/加餐 区块展示（只展示，不要求选择）
- 通知：**仅组间歇**。补货预测/低库存走首页卡片，不发通知
- 导出：JSON 全量（可回导）+ CSV 分表
- 备份三层：应用私有目录自动快照（7 份日 + 8 份周）→ 手动导出到外部（系统分享面板）→ 超 7 天未导出显示可关闭提示条

**用户坚持、我提出过风险的三点（照做但需在实现时降痛）**
1. 动作库**完全空库**（不为技术文案预置），因为要给摄像头动作识别录制样本
2. 食物库**完全空库，只手录**，不用 AI 补全 → 实现时必须提供：从最近记录复制、常用收藏、包装营养表粘贴解析、CSV 批量导入
3. 摄像头自动计次（数 reps）为主要目标，P2 分期

**摄像头方案的结论（重要）**
- 自动**计次**可行：MediaPipe Pose 33 关键点 + 关节角度状态机，纯规则零训练，单人正面/侧面 95%+
- 自训动作**分类**模型不可行：需每类 200-500 段多人多角度视频，单人 10 段必然过拟合
- 落地顺序：P1 手动录入 → P2 WebView 内 `@mediapipe/tasks-vision` + WASM 验证算法（10-15fps，发热）→ 有效再写 Kotlin 原生插件下沉
- 硬规则：摄像头计数结果必须可手动修正，且点"确认本组"才落库
- 用户主要在**健身房**使用（逆光/有人走动），识别失败必须默认降级为手动

## 技术栈版本修正（2026-10-26 追加）

用户问"我的设备是 Android，也要用 Capacitor 7 吗"。核查后修正：**Capacitor 应为 8.x，不是 7.x**（此前建议基于过时信息）。

事实基线（2026-10 实测）：
- Capacitor 8.0.0 于 2025-12-08 发布，最新稳定 **8.5.2（2026-09-11）**
- Capacitor 9 仅到 `9.0.0-alpha.7`，不可用于生产
- Capacitor 7 最新 7.6.9（2026-08-31 打过补丁），但 **targetSdk 卡在 35**
- Android 版本矩阵：Cap 8 → minSdk 24 / targetSdk 36；Cap 7 → minSdk 23 / targetSdk 35
- Cap 8 要求：Node 22+、AGP 8.13、Gradle 8.14.3、Java 21、Android Studio 当前版
- Cap 8 变化：iOS 新建工程默认 SPM（本项目不用 iOS，无影响）；Android 强制 edge-to-edge，需用新的 SystemBars 插件处理安全区

只做 Android 的可行做法：`npx cap add android` 不执行 ios，不安装 `@capacitor/ios`，工程内无 ios 目录。Capacitor 不强制双端。

**结论：技术栈定稿为 React + Vite + TS + Tailwind + Capacitor 8 + Dexie**。选 Capacitor 而非 Tauri/RN/原生 Kotlin 的理由：现有设计全部建立在 Web 技术栈 + IndexedDB/Dexie 之上，Capacitor 零阻抗复用；且 LocalNotifications（AlarmManager.setExactAndAllowWhileIdle）能满足组间歇锁屏定时。

## PRD 增补：OCR 识别营养成分表（v1.0 → 含 OCR 功能，1177 行）

**技术事实（已联网核实）**
- 引擎：ML Kit Text Recognition v2 中文 **bundled** 版，依赖坐标 `com.google.mlkit:text-recognition-chinese:16.0.1`

- 范围：**仅营养成分表**（不做配料表、条码、生产日期、净含量识别）

## 技术选型评审（用户问「PRD 技术选型是否合理」）

结论：主干合理，但有 3 个 P0 事实性缺陷 + 5 处 PRD 内部矛盾。

**P0（不修会在真机卡死）**
1. **CORS**：Capacitor WebView origin = `https://localhost`，直接 `fetch` DeepSeek 大概率被 CORS 挡。修法：capacitor.config 开 `plugins.CapacitorHttp.enabled = true`（走原生 OkHttp），注意它会破坏 SSE 流式 → AI 分析用非流式 + 60s 超时。
2. **精确闹钟**：Android 14+ `SCHEDULE_EXACT_ALARM` 不再默认授予；`@capacitor/local-notifications` 在 `allowWhileIdle:true` 时会**跳系统「闹钟和提醒」设置页并挂起**（做完一组被弹走）。修法：manifest 声明 `USE_EXACT_ALARM`（侧载不受 Play 政策约束）+ 启动时 `checkExactNotificationSetting()` 兜底。
3. **ML Kit 插件体积**：`@capacitor-mlkit/text-recognition`（v8.2.1，Capacitor>=8，3 个月前才建仓、单人维护）**一次打包全部 5 种文字模型**（Latin/Chinese/Devanagari/Japanese/Korean）。PRD O7「只装中文」在该插件上做不到，35MB 预算需重估。三选一：patch-package 删非中文 implementation / 自写 Kotlin 插件只引 `text-recognition-chinese`（~80 行）/ 预算上调至 55-60MB。

**P1**
4. **Web Audio ≠ 锁屏响铃**：WebView 后台/锁屏时 AudioContext 挂起。§5.3.5「锁屏也响」必须靠通知通道挂真实音频（res/raw/beep.wav，Android 8+ 通道建后不可改），Web Audio 只管前台最后 3 秒滴声。
5. **minSdk 24 与 Tailwind v4 冲突**：Tailwind 4 输出 oklch/@property/color-mix，需 Chrome 111+。建议 minSdk 26/29 并声明「仅 Android 8+」。

**PRD 内部矛盾/遗漏**
- consumables.initialQty 字段（§6.2）与 §7.1「不单独存字段」直接冲突。
- 训练模板表完全缺失：有 §5.3.3 结构 + workouts.templateId + M3，但 §6.2 无 workout_templates / template_blocks / template_exercises。
- 编辑/删除饮食记录时的库存回滚未定义（§7.3 只写创建路径，sourceId 已留好）。
- 导出导入合并未定义软删除行处理 → 已删数据会复活。
- L1 快照在应用私有目录，卸载即删，只防误删不防卸载；建议加 SAF 外置镜像 + gzip。
- **签名 keystore 备份未入风险列表**（keystore 丢 = 卸载重装 = 数据全毁）。

**判定为合理、不要退让的**：Capacitor 8 容器、Dexie、ML Kit bundled 方向、DeepSeek 可配 baseURL、自绘 SVG 图表、ULID、只存流水不存当前值、营养存快照、绝对到期时间戳、AI 不落库。

**开工前建议 2 小时 spike**：① CapacitorHttp 打通 DeepSeek ② USE_EXACT_ALARM 锁屏响铃 ③ 五模型 APK 体积实测。
