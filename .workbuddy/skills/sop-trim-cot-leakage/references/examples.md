# 会话泄漏示例

用来认原则，不要当填空模板。本目录会引用泄漏原句作校准，[recall-batteries.md](recall-batteries.md) 排除本 Skill 目录。

## 死引用

**泄漏：** `注册表拒绝重名（decision 7：名字扁平、不分命名空间）。`

**改：** `注册表拒绝重名；名字扁平，不分命名空间。`

HEAD 上没有「decision 7」这份东西。事实条款留下，引用删掉。有已提交主人时，改成可点的名字和路径，不要改成序号。

**泄漏：** `分层按设计稿 v2 §3.2：src/core/ 是纯核心。`

**改：** `分层：src/core/ 是纯核心。`

未提交草稿的 `§N` 解析不了。`RFC 9110 §10.1.5` 这种仓外标准可留。

## PR / 分支视角

**泄漏：** `这次 PR 给会话列表加了游标分页。`

**改：** `会话列表按游标分页。`

README 比任何一次 PR 活得长，写成当前机制。

## 变更叙事

**泄漏：** `颜色以前来自 --widget-*，谁都没定义，所以一直走回退；别名 token 修好了。`

**改：** `颜色来自别名 token；未定义的 token 走回退。`

当前机制和失败行为都留下，用现在时。故障生平属于那次提交，不属于注释。

**泄漏：** `这里以前会把多字节标签双编码。`

**改：** `没有按字节长度设防时，多字节标签会双编码。`

回归钉在现在时反事实上，不要钉在仓库史上。

## 评审场面与辩护

**泄漏：** `评审否决了缓存已解析规格。我们每次调用都重新解析。`

**改：** `规格依赖每次调用的工作目录，所以每次调用都重新解析。`

留下理由。删掉评审和轮次。

**泄漏：** `这个转型是安全的，只是 SDK 没把可选字段写严。`

**改：** `SDK 构造时填齐了所有可选字段；声明类型比运行时保证松。`

写成维护者不能破坏的不变量。「只是…」是在回答 HEAD 上没人提出的异议。

**改：** （删。下面三行代码已经是这个顺序。）

## 含糊

**泄漏：** `64KiB 缓冲对大多数情况应该够了。`

**改：** `64KiB 能装下实测最大帧 48KiB 并留余量；更大的帧在 decode 里直接失败。`

把含糊换成真实边界和越界行为。没有标记的推迟写成 `TODO(name): …`。

## 过纠

改之前先数命题。

- **义务变成认可。** 「这些直接注册是迁移到 slots 之前的例外」不能改成「这些是正式批准的例外」。
- **假想变成已交付。** 「将来的 IPC shell 会覆盖 spawn」不能改成「IPC shell 覆盖 spawn」。没有这种 shell 时写明是假想。
- **连真事实一起删。** 「通知文案既讲检查顺序，也是校验器编译对照的文本」——前半是走读，后半是耦合，只删前半。
- **去掉出处。** 「4MiB 上限是实测：生成模块最大 3.1MiB」里的「实测」要留。
