# sop-review-diff

增量审查：对刚写出的改动查过度构建，产出删除清单。只列不动手。

## 范围

1. 默认取当前未提交改动（git diff）。用户点名 commit 或任务目录才扩大，不猜、不全仓扫。
2. 点名范围之外的文件不看不报。存量代码的简化走 `sop-find-simplifications`。

## 标签

先读改动涉及的代码和调用点，理解意图再逐条判定。每条一行：`位置 标签 问题．替代方案`。

- **删除**：死代码、没人用的灵活度、为假想场景准备的功能。替代方案：无。
- **标准库**：手搓了语言或运行时自带的能力。点名该用的函数。
- **原生**：依赖或代码干了平台内置的事。点名特性。
- **过度**：只有一个实现的抽象、没人设置的配置项、只有一个调用方的层。替代方案：等第二个使用方出现再抽。
- **精简**：同一逻辑有更短写法。给出更短形式。

示例：

```
L12-38 标准库 27 行邮箱校验类．判断「@」一行即可，真校验靠确认邮件。
utils.py:L88 过度 AbstractRepository 只有一个实现．等出现第二个再抽。
L30-44 精简 手写循环拼字典．dict(zip(keys, values))，1 行。
```

## 收尾

清单末尾统计：「净效果：可删约 N 行。」没有可删项就输出「已经够精简」，停止。

## 出界

正确性缺陷、安全漏洞、性能问题不在本 skill 范围。发现了转普通审查，不写进清单。

## 不要

- 用户不点名不运行；用户说提交时不顺手运行
- 列完清单就停，不动手改代码，不接着 `sop-start-task`
- 不给存量代码做审计，那是 `sop-find-simplifications` 的事
