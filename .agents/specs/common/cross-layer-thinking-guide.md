# 跨层思维指南

> **目的**：实现功能前先梳理清楚数据如何跨层流转。

---

## 问题所在

**大多数 bug 发生在层边界，而不是层内部。**

常见的跨层 bug：
- API 返回格式 A，但前端期望格式 B
- 数据库存储 X，Service 转换成 Y 的过程中丢失了数据
- 多个层用不同方式实现了相同逻辑

---

## 实现跨层功能前

### 第一步：绘制数据流向

画出数据如何流转：

```
来源 → 转换 → 存储 → 读取 → 转换 → 展示
```

对每个箭头问自己：
- 数据是什么格式？
- 可能出什么问题？
- 谁负责校验？

### 第二步：识别边界

| 边界 | 常见问题 |
|------|----------|
| API ↔ Service | 类型不匹配、字段缺失 |
| Service ↔ Database | 格式转换、null 处理 |
| 后端 ↔ 前端 | 序列化、日期格式 |
| 组件 ↔ 组件 | Props 结构变化 |

### 第三步：定义契约

对每个边界明确：
- 精确的输入格式是什么？
- 精确的输出格式是什么？
- 可能发生哪些错误？

---

## 常见的跨层错误

### 错误 1：隐式格式假设

**坏做法**：不检查就假设日期格式

**好做法**：在边界处做明确的格式转换

#### 典型案例：日期字段 wire format 误判

后端字段类型写成 `LocalDateTime`，不代表前端拿到的一定是 ISO 字符串。

本仓库多个模块启用了 Jackson 配置 `write-dates-as-timestamps: true`，因此接口里的 `createTime`、`updateTime`、`readTime`、`dueTime` 这类字段，实际可能返回：

- ISO 日期字符串
- 10 位秒级时间戳
- 13 位毫秒时间戳
- 数字字符串形式的时间戳

错误模式：

- 前端看到字段名像 `createTime`，直接按字符串处理
- 组件里假设可以 `slice(0, 16)` 或直接原样展示
- 最终页面出现 `1776389370292` 这类原始时间戳

正确做法：

- 在后端到前端边界，把日期字段当成 wire-format 契约处理，而不是按 Java 类型猜测
- 联调或评审时，必须检查真实接口返回和模块配置
- 前端展示层统一做时间归一化，再进入格式化逻辑

### 错误 2：分散的校验

**坏做法**：同一件事在多个层重复校验

**好做法**：在入口点校验一次

### 错误 3：抽象泄漏

**坏做法**：组件直接知道数据库 schema 细节

**好做法**：每一层只了解它的相邻层

## 跨层功能检查清单

实现前：
- [ ] 已绘制完整数据流向
- [ ] 已识别所有层边界
- [ ] 已定义每个边界处的数据格式
- [ ] 已确定校验放在哪一层
- [ ] 涉及日期/时间字段时，已确认真实 wire format，而不是只看后端字段类型

实现后：
- [ ] 已用边界情况测试过（null、空值、非法值）
- [ ] 已验证每个边界的错误处理
- [ ] 已检查数据是否能完整往返
- [ ] 前端展示逻辑已覆盖 ISO 字符串、10 位秒级时间戳、13 位毫秒时间戳

---

## 什么时候需要创建流程文档

以下情况建议创建详细的流程文档：
- 功能跨越 3 个以上层
- 涉及多个团队协作
- 数据格式较为复杂
- 该功能之前出过 bug
